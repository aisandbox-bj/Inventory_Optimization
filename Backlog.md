## CRITICAL — Analyst inputs must round-trip via the exported JSON (APP-ACT-PERSIST · operator-flagged 2026-08-15)
**Operator expectation:** "drop out the JSON and the Analyst inputs will be captured there so I can upload again."
**Current reality (honest):** NOT how it works today. The For-Action flags + Analyst Recommendation live in a **browser-local sidecar** (`localStorage tune.analyst.<assessment>`), keyed by assessment name. On the **same browser** they persist + reappear when you reload that assessment — but they are **NOT written into the downloaded canonical JSON**, so re-uploading the JSON (another machine / after clearing storage) does **not** restore them.
**Scope (operator 2026-08-15): this must capture BOTH the analyst inputs AND the per-material notes.** So `APP-TREND-NOTES` stores its notes in a sidecar (same pattern as analyst-marks), and both ride the JSON round-trip.
**Fix:** on canonical-JSON **download**, co-package the analyst sidecar (**For-Action flags + Analyst Min/Max/SS + per-material NOTES**) as a separate **`_analystData` block inside the file** (OUTSIDE the schema-validated canonical structure → no SCHEMA_VERSION bump, the pipeline ignores it); on **upload**, if the block is present, restore it to the sidecar. Single-file round-trip (download → re-upload → flags + analyst Min/Max + notes restored), canonical math contract stays clean. (These are the operator's own analytical decisions — not LLM verdicts / client PII — so this respects the locked LLM-boundary principles.) **Belongs in Phase 1 — the current long-list work depends on saving/reloading analyst state + notes.**
